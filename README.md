# SlurSearchSM

Проверяет **свой** аккаунт в соцсетях на записи, за которые модерация может забанить по массовым жалобам:
оскорбительные названия групп (национальных, ЛГБТ и др.), пожелания смерти и призывы к самоубийству
(«сдохни», «выпились»), призывы к насилию, расчеловечивание групп, пропаганда самоубийства и
самоповреждения (способы, «группы смерти», pro-ana).

Зачем: аккаунты сносят массовыми жалобами. Жалобщики ищут в **старых ответах** слова-триггеры и отправляют
найденное в поддержку соцсети. Этот инструмент позволяет найти такие записи раньше них и удалить или скрыть их.

> Это поиск по словарю, а не оценка модерации. Он даёт и ложные срабатывания, и пропуски —
> каждую найденную запись смотрите в контексте.

## Сайт (GitHub Pages)

Та же проверка работает в браузере без Python: `index.html` + `web/` (логика в `web/slur_search_sm.js` повторяет
`slur_search_sm.py` и даёт такие же отчёты). Архив читается локально и никуда не отправляется.

Публикация: залейте репозиторий на GitHub → Settings → Pages → Deploy from a branch → `main`, папка `/ (root)`.
Сайт будет по адресу `https://<ник>.github.io/<репозиторий>/`.

На сайте: ссылки на поиск по аккаунту, проверка `.zip`/папки архива или CSV/JSON, те же параметры, что у скрипта,
скачивание `report.txt`, `report.csv`, `ids.txt`; PDF — кнопкой «печать → Сохранить как PDF» (ссылки остаются кликабельными).
Словари берутся из `rules/`, свой можно выбрать файлом.

Язык сайта и отчётов — русский, английский или японский — выбирается по языку браузера (остальным — английский);
его можно сменить переключателем в шапке или ссылкой `?lang=en`. Тексты интерфейса — в `web/i18n.js`.

На сайте можно выбрать соцсеть (разбор — `web/networks.js`), например:

| соцсеть | откуда записи | что проверяется |
|---|---|---|
| Bluesky | по нику через открытый API, без архива и входа | посты, ответы, репосты |
| Facebook | «Скачать информацию», формат JSON | посты, комментарии |
| Instagram | «Скачать информацию», формат JSON | подписи к постам, комментарии |
| ВКонтакте | архив данных (vk.com/data_protection), разделы «Стена» и «Комментарии» | записи на стене, комментарии |
| Snapchat | My Data, формат JSON | свои сообщения в чатах |
| Telegram | экспорт Telegram Desktop, формат «Машиночитаемый JSON» (`result.json`) | свои сообщения в личных чатах, группах (в т. ч. публичных и тех, из которых вы вышли) |

В архивах Facebook, Instagram и Snapchat нет ссылок на записи, поэтому в отчёте только текст и дата.
В Telegram ссылки (`t.me/c/…`, открываются у участников чата) есть только для супергрупп и каналов; у остальных
сообщений в отчёте указано название чата. Telegram работает и в скрипте — см. ниже.
Разбор архива ВКонтакте приблизительный (HTML-разметка архива не документирована).

Локально страницу нужно открывать через сервер (иначе браузер не даст загрузить словари):
`python -m http.server`, затем http://localhost:8000.

## Скрипт

Нужен Python 3.10+. Для PDF-отчёта нужна библиотека `fpdf2`: `pip install -r requirements.txt`.
Без неё будет только TXT.

## Шаг 1. Быстро: ссылки на поиск (без архива)

```
python slur_search_sm.py --search-links ваш_ник --only-replies
```

Создаёт `report/search.txt` и `report/search.pdf` — набор ссылок вида `from:ваш_ник filter:replies (сдохни OR выпились OR ...)`.
Откройте их в браузере, где вы вошли в аккаунт (в PDF ссылки открываются по клику). Если по ссылке ничего не нашлось, это хорошо. Уберите
`--only-replies`, чтобы проверить и обычные записи.

Ограничения: поиск соцсети находит только точные словоформы, не видит замаскированные слова (`xoхлы`) и не всегда
показывает очень старые записи.

## Шаг 2. Полностью: архив аккаунта

В настройках соцсети запросите архив своих данных («Скачать архив данных» / «Скачать информацию»).
Архив готовят от нескольких часов до пары дней, потом приходит ссылка на `.zip`.

```
python slur_search_sm.py путь\к\archive.zip
python slur_search_sm.py путь\к\архиву --only-replies --include-likes
```

Можно также передать CSV/JSON с колонками `id, text, created_at, username`.

**Telegram.** Telegram Desktop → Настройки → Продвинутые настройки → Экспорт данных из Telegram. Отметьте личные чаты
и группы (в том числе публичные), внизу окна в поле «Формат» выберите «Машиночитаемый JSON» (по умолчанию стоит HTML —
`export_results.html` и `messages.html` проверить нельзя), медиа не нужны. Передайте папку экспорта или `result.json`:

```
python slur_search_sm.py "путь\к\Telegram Desktop\DataExport_2026-10-24"
```

Проверяются только ваши сообщения, в том числе в группах, из которых вы вышли (если они попали в экспорт).
Пересланные сообщения считаются репостами (`--no-retweets` их пропускает), ответы — ответами (`--only-replies`).
В экспорте одного чата (меню чата → «Экспорт истории чата») нет данных о владельце, поэтому проверяются все участники;
чтобы оставить только свои сообщения, добавьте `--account "ваше имя в Telegram"`.
Не попадут комментарии под постами каналов, если вы не вступали в группу обсуждения, и посты ваших каналов
(в экспорте их автор — канал, а не вы).

| параметр | что делает |
|---|---|
| `--only-replies` | только ответы — по ним чаще всего ищут жалобщики |
| `--include-likes` | проверять и лайкнутые записи |
| `--no-retweets` | пропускать репосты |
| `--since / --until YYYY-MM-DD` | период |
| `--min-score N` | минимальный балл (по умолчанию 2; одиночное упоминание группы = 1 и не попадает) |
| `--ignore файл` | id уже проверенных записей, по одному на строку |
| `--rules файл` | словарь; можно указать несколько раз |
| `--format txt,pdf` | форматы отчёта (по умолчанию оба) |
| `--out папка` | куда сохранить отчёт (по умолчанию `report`) |
| `--account имя` | проверять только этот аккаунт |
| `--lang ru\|en\|ja` | язык сообщений и отчёта (по умолчанию — язык системы: русский, японский, остальным английский) |

Результат:

* `report.pdf` — записи по уровням риска, найденные слова выделены красным, ссылки открываются по клику;
* `report.txt` — то же простым текстом, найденные слова в `[квадратных скобках]`. Ссылки кликабельны
  в VS Code, Notepad++, Telegram (в стандартном Блокноте Windows — нет, копируйте в браузер);
* `report.csv` — то же для Excel (разделитель `;`);
* `ids.txt` — id найденных записей.

## Словари

`rules/default.json` — под типичные правила соцсетей (язык вражды, призывы к насилию, суицид и самоповреждение), русский и английский.
`rules/ja.json` — то же для японского (`死ね`, `チョン`, `ガイジ`, `一緒に死のう` и т. п.). Оба используются по умолчанию.
Свои словари в том же формате подключаются через `--rules` (можно несколько раз; тогда встроенные не подключаются —
укажите их явно, если нужны). Категории с одинаковым ключом из разных словарей объединяются: название и вес берутся
из первого словаря, паттерны и `search_terms` складываются.

Каждая категория даёт свой вес (один раз на запись). Сочетания дают бонус: например, «упоминание группы +
насилие» весит больше, чем каждое по отдельности. Уровни: **высокий** ≥ 6 баллов, **средний** ≥ 3,
остальное — **низкий**. Опасен уже средний уровень: одного оскорбления или «сдохни» в ответе
достаточно для жалобы.

Перед проверкой текст нормализуется: нижний регистр, `ё → е`, латинские «двойники» внутри русских слов
(`xoхлы`) заменяются на кириллицу, полуширинные и полноширинные символы (`ｼﾈ`, `ＫＹＳ`) — на обычные.

`title` — название категории или сочетания, `titles` — переводы для отчёта (`{"en": "...", "ja": "..."}`; без них везде `title`).
`patterns` — регулярные выражения: достаточно основы слова, левая граница ставится автоматически.
После японских букв (кана, иероглифы) граница не требуется — в японском нет пробелов, и `死ね` находится внутри `早く死ね`.
Поэтому короткие японские слова, которые встречаются внутри обычных, ограничивайте сами: `シナ(?!リオ)`, `(?<!必)死ね`.
`search_terms` — точные словоформы для ссылок на поиск.

## Что делать с найденным

* Удалите найденные записи. Если записей много, используйте сервисы массового удаления по `ids.txt`.
* Если бан уже случился, подавайте апелляцию через форму соцсети. Удалённые записи обычно облегчают восстановление.

Пример: `python slur_search_sm.py examples/archive --out examples/report`.
